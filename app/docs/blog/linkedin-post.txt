Most text-to-SQL accuracy talk is about the model. In my tests, the bigger lever was a plain text file.

I gave the same 7B model the same 17 questions on a Databricks dataset with no comments, with and without a written-down ontology (what the columns mean, how tables join, how the company defines revenue).

Schema only: 14 of 17 correct.
With the ontology: 17 of 17.

The three misses were not hard SQL. The model wrote valid queries that returned 0 or null: WHERE approved = 'Yes' (the value is 'Y'), paymentMethod = 'Visa' (it is 'visa'), gender = 'F' (it is 'female'). The schema says "string". It does not say which strings.

I then tried 16 prompts by hand on two running instances. Seven gave a wrong answer without the ontology and a right one with it, for example 'How many customers live in the United States?' (country = 'United States' returns 0; the data says 'USA', and franchises in the same database say 'US'). Nine made no difference.

On AdventureWorks the same pattern: 7 of 17 from the schema, 8 with the database's own comments, 14 with a hand-written ontology. Swapping models moved the score by about 2 questions.

The head-to-head I care about most: a free local 7B model with an ontology scored 17 of 17. OpenAI's gpt-oss-120b on Groq, with the schema alone, scored 15 of 17. It got the visa and female-customer questions right by itself, but still returned 0 for approved suppliers, because the value is 'Y' and only the data knows that. That is a match, not a knockout: 17 questions, one run, and one of the two misses is an ambiguous question.

What that means for cost: the local model has no per-token charge, and an ontology adds tokens, which is free locally and a multiplier on a paid model. A hosted 120B model is already cheap (about 0.01 to 0.09 cents a question at list price), so the real case for local is no per-token cost, data that stays inside, and no per-minute limits.

Going from a 1.5B to a 7B model added about 2 correct answers; the ontology added 3 to 7. I have not tested a closed frontier model.

Two things I did not expect:
- My first run showed no gain (10 vs 9). The ontology was not reaching the model: notes were only added when the question contained the exact table name. Writing it down is not enough. It has to be found.
- A SQL-specialist model (sqlcoder-7b) did not benefit from the ontology.

The limits are in the article: 17 questions, one model family, I wrote both the questions and the ontology, and I changed two questions after seeing results (disclosed, with what the score would have been otherwise).
